# SeedQueue 跑分（Benchmark）现状与优化方案

> 记录时间：2026-11-12　当前构建：`0.9.0-rc.4-build.10+26.3`

## 1. 现状

跑分已可完整执行并能被 N / Esc 取消，结果为 **29 resets / 13.91 s ≈ 2.09 RPS**（此前长期为 0.3–0.7 RPS 甚至无法启动）。

| 能力 | 状态 |
| --- | --- |
| 按 B 开始（跑分中重复按 B 被忽略） | 可用 |
| 按 N / Esc 取消（覆盖层下轮询按键） | 可用 |
| 结果面板 15 秒后消失 | 可用 |
| 逐次重置分段计时 | 可用 |

分段日志格式：

```
[seedqueue] benchmark reset 12 took 480 ms (build 2210 ms, queued 130 ms)
```

- `took`：距上一次重置的间隔；
- `build`：实例从创建到 READY（区块生成 + 预览抓包 + 冻结）；
- `queued`：READY 后在队列中等待被消费的时间。

## 2. 实测数据（40 次重置）

预热实例：

| reset | build | queued |
| --- | --- | --- |
| 1 | 5458 ms | 3362 ms |
| 2 | 5424 ms | 3394 ms |
| 3 | 5831 ms | 3070 ms |
| 4 | 5769 ms | 3132 ms |

稳态：

| reset | build | queued |
| --- | --- | --- |
| 5 | 2170 ms | 28 ms |
| 6 | 2768 ms | 42 ms |
| 7 | 3088 ms | 16 ms |
| 8 | 3391 ms | 66 ms |
| 9 | 1568 ms | 20 ms |
| 10 | 1781 ms | 65 ms |
| 11 | 2015 ms | 125 ms |
| 12 | 1673 ms | 83 ms |

**结论**：`queued` 始终很小（16–125 ms），说明队列没有积压；瓶颈完全在**单实例构建**。稳态 RPS ≈ 2.09 对应并发约 4（2.09 × 1.9 s）。

## 3. 优化方案（待执行）

按性价比排序，逐项 A/B 验证，每次只改一个变量。

### E1 提高跑分并发

- 跑分期间独立并发上限：`-Dseedqueue.benchmarkConcurrency`（默认 8），不影响日常刷种；
- 预期 RPS ×1.6–2（受 CPU 线程数限制）。

### E2 缩小跑分预览半径

- `-Dseedqueue.benchmarkChunkRadius`（默认沿用配置）；
- 半径 2 → 25 区块，半径 1 → 9 区块，生成量降至 36%；
- 预期 `build` ×0.4；代价是卡片可见范围变小。

### E3 减少每区块工作量

- 服务端设置：`spawnMonsters=false`、`spawnAnimals=false`、`randomTickSpeed=0`、最小 `simulationDistance`；
- **不可关闭 structures**：会改变速通种子；
- 预期 `build` −10~20%。

### E4 预热

- 前 4 次 `build` 5.4–5.8 s，稳态 1.7 s，差值是类加载 / JIT / 注册表预热；
- 方案：墙界面显示时先构建一个实例预热，让首次真实构建接近稳态。

### E5 降低区块状态（高风险，最后尝试）

- 预览只需要方块数据，理论上可用 `FEATURES` 而非 `FULL`；
- 26.3 中低状态区块能否直接读 BlockState 未验证，风险高。

## 4. 观测手段

- 每次重置的三段计时（已实现）；
- `-Dseedqueue.memLog=true` 记录显存/堆占用；
- 建议补充：每实例区块数日志，验证 build 与区块数是否线性。

## 5. 已知限制

- 跑分期间队列被清空时依赖补队列节奏，已加"队列为空则跳过冷却"的兜底；
- 覆盖层接管输入，取消通过 tick 轮询按键实现，不走按键事件。
